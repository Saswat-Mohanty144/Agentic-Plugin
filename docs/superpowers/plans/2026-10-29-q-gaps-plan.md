# Q1-Q7 gap closure — plan (2026-10-29)

Source: implementation-status audit (docs/superpowers/plans/2026-10-29-implementation-status.md). Owner asked to
implement everything that is not complete. Owner-only items stay parked (ADR 0001 decision, DPA/DPIA, sub-processor
list, VPC topology, real customer salary-structure rules and variance thresholds, live tenants).

Every batch: failing tests first (red count recorded), implementation, one single-invariant mutation proof, ruff,
affected suites green, commit. Full suite once per batch, under the heavy-job lock.

| Batch | Gap (audit rank) | Design decision (architect, under delegation) | Done when |
|---|---|---|---|
| QA | 1. No-LLM-Numbers | Monetary tool arguments are marked `x-monetary` in the tool schema. The orchestrator only accepts such a value if the same number appears in the user's own messages in this conversation (grounding check); otherwise the tool is not run and the model gets `UNGROUNDED_AMOUNT`. Results from amount-taking tools carry `input_source: USER_STATED`; record-based tools (PF) carry `HOST_RECORD`. Eval case `uae-gratuity-amount` updated. | A hallucinated or altered amount never reaches a calculator; tests cover exact and digit-formatted matches (1,20,000 / 120,000 / 120000.00 all equal 120000), word forms ("1.2 lakh", "120k") which are not accepted so the model must ask, and absent numbers |
| QB | 3, 4, 5. Canonical salary + checks, provenance, variance | Canonical `SalaryFacts` (annual_ctc, gross_monthly, basic_monthly, dearness_allowance_monthly, pf_wage_monthly, currency, period) with cross-checks (no negatives, basic+DA <= gross, gross*12 <= ctc when both known, currency matches jurisdiction). PF results persisted with provenance (fingerprint, rules version, source fields, inputs). Month-over-month variance vs the previous persisted period: threshold from the tenant payroll rules (`variance_review_percent`); above it the result is returned with `review_required: true`; no threshold configured -> `variance_check: NOT_CONFIGURED` (never a guessed threshold). Missing inputs -> `MISSING_INPUT` with the field names. | Two tenants with different rules give different, correct PF; a drift in inputs is flagged; every result is traceable |
| QC | 2. Approved mapping on the read path | Requisition reads resolve fields as: tenant's approved mapping version (override) > vendor profile default; pending (unapproved) LLM suggestions are never used. The response reports which layer and version served each field. | A tenant override changes what the connector returns; an unapproved proposal changes nothing |
| QD | 6. PII classification | `/v1/schema/introspect` returns types and structure only (no raw sample values). Mapping approval requires a classification for every mapped field (`PII`, `COMPENSATION`, `INTERNAL`, `PUBLIC`) and an `llm_visible` flag; unclassified = PII. Tool outputs sent to the LLM drop fields of approved mappings that are not `llm_visible`. | No raw sample value leaves introspect; approving without classification is refused; a non-visible field never reaches a prompt |
| QE | 7, 8. Drift, tool subsets, rate limit | Wire drift detection for host requisition payloads (unknown shape -> quarantine, like PF). Tools offered to the model are narrowed by a deterministic intent pre-classifier (keyword/permission based, falls back to all permitted tools when unsure). Per-tenant request rate limit (token bucket) on LLM-backed routes -> 429 `RATE_LIMITED`. | Drifted requisition payload is quarantined; a payroll question sends only payroll tools; burst over the limit is 429 |
| QF | 9. Data tier, residency, retention | `LlmPolicy.max_data_tier` (1 schema-only, 2 pseudonymised, 3 raw) per provider and `region`; a request whose tier exceeds the provider's tier is refused. Egress rows older than `egress_retention_days` are purged; deletion on request by tenant. Values per tenant are owner inputs; defaults fail closed (tier 1). | Tier and region enforced in the gateway; retention purge tested |
| QG | 10, 11, P11. Evals, second vendor, MCP | Eval runner reports tokens per answer and citation correctness (citations must come from tool/RAG output). Declarative Zoho People requisition profile built from the public API docs, contract-tested with a recorded-shape fixture (labelled as doc-derived, not a live capture). `HrmsMcpServer` becomes a thin adapter over `AgenticToolRegistry` (same validation, tenant from an `AuthContext`, never from arguments). | Second declarative vendor with zero engine changes; MCP shares the validated path |
| QH | Coverage | Tests for files under 85% line coverage, including `hrms_plugin/connectors/` (kept by owner decision). Acceptance: per-file coverage target met and a sampled mutant per file is killed. | Coverage report attached |
